RES.8: SEO libraries and markup

Research thread A, 2026-10-17. Unblocks SEARCH.9; feeds UI.2, UI.9, GIT.6 and RND.4. The search engines' own documentation sites were not reachable from this session, so rules that come from them are stated from general knowledge and marked.

Recommendation

  • No SEO library. Everything needed is a template and about 60 lines of standard-library Python. The sitemap writer produced a 50,000-URL, 4.3 MB sitemap in 25 ms and the result parsed as well-formed XML. Libraries examined add dependencies for what a Jinja template does: feedgen 1.0.0 (LGPL-3.0-or-later, last release 2023-12) for Atom feeds is the only one worth a note, and the recent-changes feed (LNK.7) is also a small template.
  • Server-rendered public pages (already planned as UI.2) are the SEO foundation: complete HTML, no script needed to read, the rendered body from the cache. All markup below goes in the page <head> and costs no JavaScript.
  • Canonical URL from configuration, not from the request. Build <link rel="canonical">, sitemap and Open Graph URLs from a configured site.base_url (HTTPS, as decided: Apache handles TLS). Using the Host header would let anyone poison a cached page with a foreign host name.
  • Per-page head (all from page data, all escaped by Jinja autoescape): <title>Page title - Site</title>, <meta name="description"> from the page summary (cut at about 160 characters at a word boundary), canonical link, <meta name="robots"> where needed, Open Graph (og:title, og:description, og:type=article, og:url, og:site_name, og:image using the 1280-wide variant of the page's cover image when it has one) and Twitter card tags (summary_large_image when there is an image, else summary).
  • Structured data as JSON-LD, one block per page: Article (headline, dateModified, inLanguage, isPartOf the site's WebSite, license = the CC BY-SA 4.0 URL) and a BreadcrumbList for type, setting and page. Do not mark up reviews, ratings or people. Do not add a SearchAction (sitelinks search box): Google announced it would stop showing that feature in late 2024 (from memory, could not be re-checked now), so it earns nothing.
  • Sitemaps: /sitemap.xml is a sitemap index pointing to files of at most 45,000 URLs (the protocol allows 50,000 URLs and 50 MB uncompressed each, from the sitemaps.org protocol as I know it; its site was not reachable to re-check). Include only public pages, with lastmod = the date of the last revision. A queue job writes the files into the cache directory after content changes (debounced to once a minute) and Apache serves them as static files; lastmod is cheap because page.updated_at exists.
  • robots.txt generated from configuration: allow everything public, Disallow: /api/, /admin, /account, /search, history and diff paths, plus Sitemap: with the absolute URL. (Blocking in robots.txt stops crawling, not indexing; see the next point.)
  • noindex by header. Send X-Robots-Tag: noindex, nofollow from Flask on edit, history, diff, login, account, search-result and error pages, and on every response to a logged-in user. Search engines must be able to fetch a page to see its noindex, so such paths are not also blocked in robots.txt (history and diff are blocked for crawl budget only; accept that).
  • GM-only pages never leak through SEO. They are absent from the sitemap, from Open Graph, from the JSON-LD of other pages (a link to them is not rendered for anonymous readers), and an anonymous request answers 404, not 403, so their existence is not revealed (VIS.2, VIS.3).
  • Renamed pages redirect. When GIT.6 renames a slug, the old slug stays as an alias and answers 301 to the new canonical URL. Without this, every rename loses the page's search ranking and breaks inbound links.
  • Licence markup: the footer link to CC BY-SA 4.0 gets rel="license" (UI.9) and the JSON-LD license property, which tells reusers and crawlers the content terms.

Checks that ran

  • JSON-LD under a strict CSP. A page with Content-Security-Policy: default-src 'none'; script-src 'self'; style-src 'self' and an inline <script type="application/ld+json"> block (Chromium 141): the block was readable from the DOM and the console showed no CSP violation. JSON-LD is data, not executed script, so the strict policy needs no exception. Generate it with json.dumps and replace </ with <\/ so no page text can close the script element.
  • Sitemap generation: 50,000 <url> entries with xml.sax.saxutils.escape, 25 ms, 4.3 MB, parsed back by xml.etree without error. Paths must be percent-encoded as well as XML-escaped (page names contain apostrophes and accents); use urllib.parse.quote on slugs, which GIT.6 already restricts.

HTTP caching for readers and crawlers

  • ETag = hash of (content commit, render version, allowlist version); the same value keys the rendered-page cache (caching). Conditional requests answer 304 without touching the renderer. Crawlers use it.
  • Cache-Control: public, max-age=300 on anonymous, public pages; private, no-store on anything seen by a logged-in user or touching GM-only content, so no shared cache can leak a GM page. Vary: Cookie on pages whose appearance depends on the session.
  • Compression: Apache mod_deflate (the rendered 9.7 KB sample page gzipped to 0.7 KB with zlib, so HTML compresses about 13 times).
  • Page speed: reading pages need one stylesheet and no script; images use the width ladder with srcset and explicit width and height from the media table (no layout shift), and loading="lazy" below the fold (MED.7, UI.2).

Items this changes

  • SEARCH.9 gains: canonical from configuration, noindex header rules, GM-only exclusion test, sitemap index and queue job, JSON-LD without SearchAction, 301 for renamed slugs (GIT.6 adds the alias redirect).
  • UI.2 and UI.9: head template, rel="license".
  • MED.7: alt text is part of the media: syntax and required by the editor (also an accessibility rule, RES.18).

What could not be verified

  • Search engines' current guidance: Google's structured-data and sitelinks documentation and the sitemaps.org protocol were unreachable (connection refused by the session's proxy). The limits and the sitelinks search-box change are from memory.
  • Whether crawlers pick up the images in JSON-LD or Open Graph: not tested; no external crawler is available.
  • Core Web Vitals scores: no real page exists yet; re-measure after UI.2 with Lighthouse (Apache-2.0, 13.5.0 on npm).
