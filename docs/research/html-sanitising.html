RES.3: HTML sanitiser and the admin allowlist

Research thread A, 2026-10-17. Unblocks RND.3 and AUTH.9; feeds RND.4. Experiments on Ubuntu 24.04.5 with nh3 0.3.7 and bleach 6.4.0 installed from PyPI.

Recommendation

  • nh3 0.3.7 (MIT, Python binding to Rust's ammonia sanitiser; wheels for every common platform, including Python 3.12 on Linux). Not in Ubuntu 24.04's archive, so it comes from the pinned virtualenv (RES.15). Roughly 30 times faster than bleach in the test below.
  • Allowlist, not blocklist. One sanitiser pass over the whole rendered HTML (Markdown output and author-written raw HTML together). The tag and attribute allowlist is the fixed baseline that Markdown produces (paragraphs, lists, tables, headings, code, links, footnotes, definition lists, abbreviations, sub/sup) plus whatever the admin approves. An author who types raw <table> gets what Markdown would have given them anyway; anything beyond the baseline is stripped until an admin approves it (AUTH.9).
  • Build the nh3 Cleaner once per allowlist version and cache it in the process. The html_allowlist table (tag and optional attribute rows) maps directly onto the Cleaner's tags and attributes arguments. Changing the allowlist bumps a version number that also invalidates rendered pages (caching).
  • Some things the admin cannot approve: script, style, iframe, object, embed, form and form controls, link, meta, base, svg, math (our own maths is inserted after the sanitiser), template, noscript, and every on* and style attribute. The approval API rejects these names.
  • Rules applied through nh3's attribute_filter and options (all tested): id values get a user-content- prefix (stops DOM clobbering and anchor collisions; nh3 also has an id_prefix option), class keeps only names starting with u-, href allows http, https, mailto and relative URLs only (and drops protocol-relative //host), img src only allows our own /media/ paths (an external image would leak readers' addresses and violates the CSP img-src 'self' anyway), strip_comments is on.

Experiments

XSS corpus, nh3 and bleach side by side

23 inputs (script tags, event handlers, javascript: and data: URLs including whitespace-obfuscated, SVG with onload, style attributes, <style> with @import, iframe, form, MathML xlink:href and mglyph mutation, noscript mutation, conditional comments, nested broken tags, meta refresh, base, link, protocol-relative URLs) through the same allowlist. Speed

A 24.9 KB rendered page (the sample document repeated 30 times): nh3 0.99 ms, bleach 30 ms per clean (mean of 50). Both are small next to Markdown (about 13 ms for the same page) but nh3 keeps the preview endpoint and bulk reindexing cheap.

Allowlist mapping, tested

cl = nh3.Cleaner(
    tags=baseline_tags | approved_tags,
    attributes=baseline_attrs merged with approved (tag, attr) rows,
    attribute_filter=filt,            # id prefix, u- classes, img /media/ only, no //host
    url_schemes={'http', 'https', 'mailto'},
    link_rel='noopener noreferrer',
    strip_comments=True,
)
filt('p', 'id', 'x')                                -> 'user-content-x'
filt('p', 'class', 'u-note admin-banner')           -> 'u-note'
filt('img', 'src', 'https://evil/x.png')            -> None   (attribute removed)
filt('img', 'src', '/media/ab/cd/x/full.webp')      -> unchanged
filt('a', 'href', '//evil.example')                 -> None

Results of the exact calls above: <p id="x" class="u-note admin-banner"> became <p id="user-content-x" class="u-note">; the external image lost its src; the /media/ image stayed; the protocol-relative link lost its href; mailto: and /wiki/x stayed.

Details for RND.3

  • nofollow on external links only. nh3's link_rel applies to every link, including internal wiki links, where nofollow is wrong for search engines (SEO). Set link_rel to noopener only, and let a Markdown tree processor add rel="nofollow ugc" to external links before sanitising (allow the rel attribute on a with a filter that only accepts those tokens).
  • Footnotes need id, href and the classes footnote-ref, footnote-backref: add these as baseline u--style exceptions or rename them in a Markdown extension; do not open class in general.
  • Table alignment arrives as style="text-align:right"; convert to a class before sanitising (see RES.1); the sanitiser strips every style attribute.
  • Order matters: sanitise after Markdown and before inserting trusted markup (maths, media players). The renderer's own output is never passed through the sanitiser again, and author text is never concatenated into it unescaped.
  • Test set: keep the 23 inputs as a regression test, and add tests for every approved tag. The inputs are in docs/research/poc/sanitiser_vectors.py (it also prints the speed comparison); they belong in the test suite (TST.1).
  • Defence in depth: the CSP (default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self') is the second wall; verified in Chromium 141 that inline scripts and inline style attributes are refused (see the front-end page). The sanitiser is the first.

Alternatives considered

Mozilla announced it deprecated in January 2023 (from memory; the current PyPI description does not say so and I could not verify the announcement), another reason not to start a new project on it.
Own sanitiser (html.parser or lxml)Rejected: sanitising HTML correctly (mutation XSS, parser differences) is the thing libraries exist for.
DOMPurifyJavaScript; would need Node and a DOM implementation on the server. Rejected.
