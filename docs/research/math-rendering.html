RES.2: Server-side LaTeX math

Research thread A, 2026-10-17. Unblocks RND.2; touches RND.4 (CSP), RND.5 (cache) and UI.14. Experiments on Ubuntu 24.04.5 with Chromium 141 (Playwright) for the browser checks.

Recommendation

  • Render LaTeX to MathML with Temml 0.14.0 (MIT, by the KaTeX author) in a small Node batch script, called once per page render with every formula on the page. Output is MathML Core with no fonts, no script and almost no inline style, so it fits the strict CSP and inherits text colour (dark mode works with no extra work).
  • Node.js is a runtime dependency only for this. Ubuntu 24.04's nodejs package is 18.19.1; Temml needs 18.13 or newer. Vendor temml.min.js (164 KB) in the repository so no npm install is needed on the server. If Node is missing or fails, the page still renders: the formula is shown as escaped TeX in a <code class="math-error"> element and the failure is logged. Whether a Node runtime is acceptable overlaps RES.22 (owned by Research C); see the decision below.
  • The renderer's output is trusted markup inserted after sanitising, never author HTML. Author text only ever reaches Temml as a TeX string, with trust: false, maxExpand: 1000, and an error (not a guess) on bad input.
  • Add one small CSS file (Temml's Temml-Local.css, 12 KB, MIT) served from our origin, and optionally the Latin Modern Math webfont for identical look across browsers. Both are same-origin, so style-src 'self'; font-src 'self' covers them.
  • Delimiters accepted: \\( ... \\), \\[ ... \\] and the single-backslash forms (MultiMarkdown writes two). Dollar signs are not math (game text uses prices and dice, for example "$5"). The Markdown parser never sees the TeX: the prototype hides each formula behind an inert token and swaps the MathML in after sanitising.

A 14-formula coverage test (aligned, cases, blackboard bold, \operatorname, binomials, nth roots, vectors, overlines, \text mixed with maths, calligraphic, \dfrac, norms, a damage formula) rendered without error in KaTeX and Temml; the only failure was \ce{H2O} in KaTeX (needs an extension there, supported by Temml).

Security checks

  • With trust false, Temml and KaTeX never emit an href for \href{javascript:alert(1)}{x}: both print the command name in an error colour and the arguments as plain math symbols (the error colour is an inline style, stripped server-side). \includegraphics gave an error element in Temml.
  • A recursive macro (\def\a{\a\a}\a) returned an error in KaTeX and Temml thanks to maxExpand; latex2mathml stopped with a RecursionError at depth 100.
  • Browser test (Chromium 141) with script-src 'self'; style-src 'self': Temml's MathML rendered correctly in light and dark colour schemes, display math stayed display:block from the CSS class although the style attribute was refused, and matrices only lost their small cell padding. Add mtd { padding: 0 .4em } to the shipped CSS and strip the style attributes server-side (the prototype does) so the console stays free of CSP violations.
  • The renderer runs on the worker or in the web process with a timeout (the prototype uses 10 s) and a size cap on the input (suggested: 2,000 characters per formula, 200 formulas per page).

Browser support

MathML Core renders natively in current Chrome and Edge (109 and newer), Firefox and Safari; that is stated from general knowledge and from the Chromium 141 run here, not from a compatibility database (the sites hosting one were not reachable from this session). Older browsers show the plain text content of the formula. Because this is a game database and not a mathematics site, that is acceptable; the editor guide (DOC.4) mentions it.

Pipeline and cost

Parse Markdown, sanitise, then replace tokens with MathML (see RES.1 and RES.3). Starting Node costs about 60 ms per page that contains formulas, paid only on a cache miss: pages are cached by revision (caching), so each revision pays once. The preview endpoint (RND.6) pays it on every preview of a page with math; if that is felt, keep one long-lived Node process on a local socket (not planned for 1.0). Prototype files: docs/research/poc/math_batch.js and render_poc.py.

Fallback if Node is not accepted

Use latex2mathml with guards: reject any output containing a backslash token in an <mi>, a raw ampersand or an href attribute, and show the TeX source for rejected formulas. Everything except simple formulas (no aligned, no \ce) would show as source. Acceptable for 1.0 if Node is ruled out; a worse editor experience.

Decision for the owner

Question: may the server run Node.js (Ubuntu's nodejs package) at runtime only to render maths?

Options: (a) Yes, Temml via Node, recommended: best output, real errors, safe; adds one apt package and one vendored file, and degrades to TeX source if Node is missing. (b) No Node: latex2mathml with guards; pure Python, simple formulas only. Default taken: (a), pending RES.22 (build-time Node) from Research C; switching to (b) later only changes RND.2.

What could not be verified

  • MathML browser support tables (hosts blocked); Safari behaviour was not tested.
  • Whether Node 18.19 (Ubuntu) and Node 22 (used here) render identically: only Node 22 was run. Temml declares node >= 18.13.
