PlanResearch: media processing

Media processing research

Question: which tools and Python libraries do we need to process image and video uploads with ffmpeg and ImageMagick, and what else does the stack need? Findings come from established practice and package knowledge; versions should be re-checked against Ubuntu 24.04 when 0.1 starts.

Approach

Uploads are never processed in the web request. The upload handler stores the file in quarantine and enqueues a Redis task; a worker validates and transcodes it, then publishes or rejects it. The command-line tools run as subprocesses with an argument list (no shell), resource limits and timeouts, as an unprivileged user, because both tools have long histories of parser vulnerabilities.

ImageMagick on Ubuntu ships a policy.xml; we tighten it (disable risky coders such as MVG, MSL, URL, HTTP, and text/script-reading coders, set memory, map, disk and time limits). Run it as magick or convert depending on the packaged version.

Processing rules per upload class

ClassPipeline
Images (PNG, JPEG, GIF, WebP)Sniff, Pillow decode check and pixel limit, ImageMagick re-encode with metadata stripped (-strip, auto-orient), make thumbnails. The re-encoded copy is what gets served.
Video (default allowed: MP4, WebM, MOV input)ffprobe check (streams, duration and size limits, no external references), ffmpeg transcode to H.264/AAC MP4 and optionally VP9/Opus WebM, metadata stripped, poster frame extracted. Limit protocols with -protocol_whitelist file. Original discarded or kept in quarantine by setting.
AudioOff by default; if enabled, same ffprobe/ffmpeg path.
SVGOff by default (can carry script). If enabled, rasterise to PNG rather than serving the SVG.
PDF and othersOff by default; admin may enable. Not processed by ImageMagick (Ghostscript policy stays disabled).

Risks and mitigations

  • Parser exploits: unprivileged user, no network (systemd sandboxing or unshare), CPU/memory/time limits, current distribution security updates.
  • Decompression bombs and huge frame counts: Pillow MAX_IMAGE_PIXELS, ImageMagick policy limits, ffprobe-based checks before transcoding.
  • Long jobs: run in the worker with a hard timeout; the UI shows "processing" until the task completes.
  • Failed files stay in quarantine and an admin can review them (the existing override path).

Recommendation

Use apt ffmpeg and imagemagick via subprocess, plus Python Pillow, python-magic, redis, rq, Jinja2, nh3, argon2-cffi, and a MySQL driver. Avoid Wand and ffmpeg-python for isolation and fewer dependencies. Open item: choose the math renderer in 0.3.
