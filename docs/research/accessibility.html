RES.18: Accessibility checklist (WCAG 2.2 AA)

Research thread B, 2026-10-17. Unblocks OPS.4; supplies the content for UI.13 (the acceptance checklist every UI item meets). Standard: WCAG 2.2 level AA.

Recommendation

  • Target WCAG 2.2 AA for every screen and for rendered content; treat the checklist below as part of "done" for each UI item (UI.13), checked while building, not in a final pass.
  • Test with both machines and people: an automated axe-core run on every key page in the daily CI job, plus a manual keyboard and screen-reader pass before each release (OPS.4).
  • Keep the editor a plain Markdown textarea in 1.0 (no rich-text widget); it is the most accessible option and matches the decided Markdown-only content model.

Standard facts

  • WCAG 2.2 became a W3C Recommendation on 5 October 2023 (confirmed by several secondary sources; w3.org itself was not reachable). It adds nine success criteria and removes 4.1.1 Parsing. The ones at level A and AA that matter to this site: 2.4.11 Focus Not Obscured (Minimum), 2.5.7 Dragging Movements, 2.5.8 Target Size (Minimum), 3.2.6 Consistent Help, 3.3.7 Redundant Entry, 3.3.8 Accessible Authentication (Minimum). Criterion numbers and levels were confirmed by search; the exact thresholds below (24 CSS pixel targets, and so on) are from my own knowledge of the standard and should be read in the normative text when UI.13 is finalised.
  • Status of WCAG as a legal requirement differs by country and by the owner's situation; this research does not give legal advice. It is mentioned because EU rules for many commercial sites follow WCAG-based standards (from memory).

The checklist

Each item is a testable statement. "Auto" means axe-core can detect most failures; "manual" means a person must check.

Captions and transcripts for uploaded media

WCAG requires captions for prerecorded video with audio (1.2.2, level A) and a text alternative for audio-only (1.2.1, A). The site cannot make users' recordings accessible, but it can make accessibility possible: the media pipeline accepts an optional WebVTT caption file per video (and a transcript page link per audio file) and the renderer emits a <track kind="captions">. An edit-screen reminder asks uploaders to add one. This is a new suggestion for the TODO (a MED item after MED.7); until it exists, the licence and upload pages should state that uploaded video should carry captions.
