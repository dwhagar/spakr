Database design

Status: draft design for review, written before any code. MySQL 8, InnoDB, character set utf8mb4, collation utf8mb4_0900_ai_ci. Migrations are managed with Alembic. Timestamps are UTC DATETIME(6).

Principles

  • One world per install: there is no world or campaign key on any table. The three settings (high fantasy, modern / cosmic horror, science fiction) are rows in setting linked to pages by tag.
  • Git holds the text: the Markdown body lives in the content repository at <type>/<slug>.md. MySQL holds identity, structured fields, relations, visibility and a search index, and can be rebuilt from git plus a fixed export of the non-git tables. page.current_commit records the commit the index reflects.
  • Class-table inheritance: page holds what every page shares; one small table per entity type holds that type's fields, keyed by page_id.
  • Visibility: page.visibility is public or gm. Every query that returns pages, links, relations, search hits, history or attached media joins to page and filters on it; the API layer builds those queries in one place.
  • Foreign keys are enforced. Soft delete (deleted_at) for pages, users and media; hard delete only by admin purge.
  • Free-text rules content (stat blocks, costs, dice) stays in the Markdown body; typed columns are for browsing and filtering only.

page_search

The search index: one row per page, holding everything searchable. Rebuilt by the worker from git and updated on every page save; it is never the source of truth.

ColumnTypeNotes

FULLTEXT ft_all (title, summary, aliases_text, tags_text, fields_text, body)full-page content search
index (type, visibility)field filters

Search modes: content search queries ft_all (natural or boolean mode) with relevance ranking and snippets cut from body; field search combines it with exact filters on type, setting (through page_setting or settings_text), tag (through page_tag) and the type-table columns; name search queries ft_name and prefix-matches title and aliases. Visibility is always applied in the same query. InnoDB full-text uses the default parser unless the admin switches to ngram for non-space-delimited text.

Key indexes and constraints

  • page (type, slug) unique; page (visibility, updated_at); relation (to_page_id, relation_kind_id) for backlinks; api_key (prefix); media (sha256) unique.
  • Check in the service layer, not the database: a non-admin API key may not carry a permission its owner lacks.
  • The place hierarchy and nation territory are trees and graphs resolved with recursive CTEs (MySQL 8).

Open design points

  • Whether the typed-field columns are worth keeping once pages exist, or whether front matter plus the search index is enough.
  • Whether fields_text can be dropped once typed-field filters query the type tables directly; kept for now so one index serves both.
  • Visibility groups: the reserved visibility_group_id columns on page and page_search are the hook; the group table and rules are post-1.0.
