spakr plan

spakr is a free form game database: everything a tabletop or story game needs to run, across three settings (high fantasy, modern / cosmic horror, science fiction). Content is Markdown and LaTeX only, versioned in git, served by Apache with Python.

Goal for 1.0: a working, functional, usable web site. Anything not needed for that sits after 1.0. Version 0.9 is the pre-release working version.

Plan documents

  • Roadmap to 1.0: the version tree from now to the first functional release, what works at each version, the critical path and what waits on the owner.
  • Phases and version numbers: 0.0 (research) to 0.9 (pre-release working version) to 1.0, every item with what it needs.
  • Dependency tree: the same plan as a tree from the earliest foundations.
  • Components: every component the software needs to be operational, security first, mapped to TODO items with gaps flagged.
  • Architecture: stack, process model, queue, repository layout.
  • Data model: entity types and how they relate.
  • Content, rendering and security: Markdown, LaTeX, HTML allowlist, git revisions, uploads.
  • Platform services: Flask API, accounts and roles, API keys, email, media storage, caching, SEO, User-Agent.
  • Database design: MySQL schema with ER overview (draft).
  • Deployment: Ubuntu, Apache, MySQL, Redis, example vhost.
  • Open questions and defaults chosen

Licences and notices: code is MIT, content is CC BY-SA 4.0, and the copyright notice and removal-request process is in COPYRIGHT.md.

Principles

  • No HTML authored by users beyond an admin-approved allowlist of simple tags. No CSS or JavaScript inside content, ever.
  • Git is the source of truth for page text and history; MySQL is the index and holds accounts, relations and settings.
  • Configuration is in JSON files that are git-ignored; only *.example files are committed.
  • Safe by default: uploads are restricted to a safe list; admins opt in to more.
