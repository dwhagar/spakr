Architecture

LayerChoice

Process model

  • WSGI app: all page views, editing, login, search. Small framework (default: plain WSGI with a thin router, no heavy dependency).
  • CGI: kept for tiny, isolated endpoints (health check, upload receiver if separate privileges are wanted). Same code library as the WSGI app.
  • Worker: systemd service consuming the Redis queue. Jobs: render cache warm, reindex, upload scanning and thumbnails, git maintenance (gc), backups.
  • Git writes are serialised with a lock so concurrent saves cannot corrupt the repository. Each save is one commit authored by the logged-in user.

Repository layout

src/            all source code
  html/         web site code (WSGI app, templates, static files)
docs/           archive, research, design, plan (plan is HTML for GitHub Pages)
examples/       Apache vhost, systemd units, config.json.example
scripts/        maintenance scripts (backup, migrate, reindex)

Configuration

Runtime settings (database credentials, Redis URL, content repo path, upload limits, secret key) live in JSON files outside version control. .gitignore ignores every *.json. Examples are committed as *.json.example. Admin-editable settings live in the database.
