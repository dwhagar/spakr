Roadmap to 1.0

The route from today (version 0.0, research and planning) to 1.0, the first functional release. It is built from the TODO list (345 items, 55 done) and the research pages, and it is regenerated from TODO.md so the counts stay true. Each version below says what is demonstrably working when it is finished and what must pass before the next one starts.

Version numbers are MAJOR.MINOR.BUILD: the phase is the MINOR number, BUILD counts pushes to main, and 1.0 is a decision, not a countdown. Every phase is responsive and works in light and dark from its first screen.

Version tree

  • Decision Two-factor sign-in (SEC.12, phase 0.4): include TOTP with recovery codes in 1.0, optional for users and requirable for moderators and admins (recommended), or after 1.0.
  • Decision Minimum password length (see open questions; 15 characters is the default).
  • Action Enable GitHub Pages from /docs (DOC.2) so these pages are published.

Decided and recorded

  • One world per install; a GM-only flag in 1.0 with a reserved visibility group column.
  • Flask API at /api/v1 with a first-party JavaScript client; invite-only sign-up; roles reader, editor, GM, mod, admin.
  • Git is the source of truth for page content; MySQL is the rebuildable index plus accounts, settings and audit.
  • No Node.js anywhere; maths in pure Python; ImageMagick and ffmpeg for media.
  • Security first; checksums and par2 parity from the ground up; nightly backups in /data/backups with a redacted config.
  • Application shell: top bar with logo and tabs, hamburger drawer on the left, page rail on the right, footer with version, licence and GitHub link.
  • Left out of 1.0 on purpose: templates and transclusion, watch lists, talk pages, reader reports, open sign-up, service workers.
