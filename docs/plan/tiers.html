Phases and versions

The plan is a ladder of phases matched to version numbers: 0.0 is now (research and planning), 0.1 to 0.8 are building blocks that each add tested pieces the next one stands on, 0.9 is the pre-release working version (installable and usable for real), and 1.0 is the release. Dates are intentionally absent.

Every work item is in TODO.md as [CAT].[NUMBER], grouped under one GitHub issue per category. Each item names the items it needs, and no item needs anything from a later phase, so the phases can be built strictly in order. The tables below are generated from TODO.md; if they disagree, TODO.md wins. The same dependencies drawn as a tree are on the dependency tree page.

Standing requirement: responsive and dark mode

From the first screen on, everything is responsive and has light and dark modes (following the system setting, with a user toggle). That includes rendered tables, code blocks, media players and these docs pages. It is built in phase 0.1 (UI.11 to UI.13), sits ahead of all other UI work in the tree, and UI.13 is the checklist every later UI item must meet.

Version numbers

MAJOR.MINOR.BUILD. BUILD counts up with every push to main. MINOR and MAJOR are the phases on this page, planned and changed by hand in the VERSION file, never stamped automatically. The current stamp is 0.0.0.

How BUILD is stamped: scripts/version.sh prints MAJOR.MINOR from VERSION plus a BUILD equal to the number of first-parent commits on main since the commit that last changed VERSION. The build restarts at 0 whenever the minor or major changes. No workflow is needed, so continuous integration stays limited to the daily schedule.

Content search

Search is planned as two things sharing one index: a full page index (the page_search table in the database design) and search fields (type, setting, tag, name and type-specific fields as exact filters). The index is written on every page save (SEARCH.2, phase 0.2) and queried from 0.6 (SEARCH.3 to SEARCH.8) once the approach research (RES.7) is done. GM-only pages are excluded for users without the GM role in the same query.

Continuous integration

Code-testing CI runs only every morning at 07:00 UTC (.github/workflows/tests.yml, cron 0 7 * * *) and can be started by hand. It does not run on pushes or pull requests unless specifically asked.

Definition of "working" for 0.9 and "usable" for 1.0

  • A new admin can follow the deployment doc and have a running site (OPS.7, DOC.3).
  • Editors can create, edit, view history of, and revert any page type through the browser.
  • Target platform is Ubuntu 24.04 LTS; Ubuntu 26.04 LTS is best effort and fixed as found.
  • Readers can browse and search without logging in (default; configurable).
  • Every feature is reachable through the API with permissions; the web UI is a JavaScript client of that API and uses nothing else.
  • No content path can produce script, inline style, or unapproved HTML.
  • GM-only pages never appear in views, search, links, backlinks, history or downloads for users without the GM role.
