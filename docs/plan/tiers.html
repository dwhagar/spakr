Tiers and versions

The plan is a ladder of versions from 0.0 to 0.9, then 1.0. Every 0.x is a non-operational building block: it adds tested pieces that the next tier builds on, but the site does not work end to end until the web UI and hardening tiers land. 1.0 is the first working, functional, usable web site. Dates are intentionally absent.

Work items are listed in TODO.md as [CAT].[NUMBER] and grouped under one GitHub issue per category. The tier table below is generated from that list; if they disagree, TODO.md wins.

Version numbers

MAJOR.MINOR.BUILD. BUILD counts up with every push to main. MINOR and MAJOR are planned (the tiers below) and are changed by hand in the VERSION file, never stamped automatically. The current stamp is 0.0.0.

How BUILD is stamped: it is not stored in a file that every push would have to edit. scripts/version.sh prints MAJOR.MINOR from VERSION plus a BUILD equal to the number of first-parent commits on main since the commit that last changed VERSION. The build therefore restarts at 0 whenever the minor or major changes, and counts up by one for each commit pushed to main. The installer and deployment script run it once to write the version into the installed package. No workflow is needed, so continuous integration stays limited to the daily schedule.

Content search

Search is planned as two things sharing one index: a full page index (the page_search table in the database design, holding title, summary, aliases, tags, settings, type-field text and the plain text of the whole page) and search fields (type, setting, tag, name and type-specific fields as exact filters). The index is written on every page save (SEARCH.2, tier 0.2) and queried from tier 0.6 (SEARCH.3 to SEARCH.8). GM-only pages are excluded for users without the GM role in the same query.

Continuous integration

Code-testing CI runs only every morning at 07:00 UTC (.github/workflows/tests.yml, cron 0 7 * * *) and can be started by hand. It does not run on pushes or pull requests unless specifically asked.

Definition of "usable" for 1.0

  • A new admin can follow the deployment doc and have a running site.
  • Editors can create, edit, view history of, and revert any page type through the browser.
  • Target platform is Ubuntu 24.04 LTS; Ubuntu 26.04 LTS is best effort and fixed as found.
  • Readers can browse and search without logging in (default; configurable).
  • Every feature is reachable through the API with permissions; the web UI is a JavaScript client of that API and uses nothing else.
  • No content path can produce script, inline style, or unapproved HTML.
  • GM-only pages never appear in views, search, links, backlinks, history or downloads for users without the GM role.
